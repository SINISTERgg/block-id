FEATURE 01

W3C Verifiable Credentials & Dynamic Schema Builder

Identity & VC

Issue cryptographically signed, tamper-evident digital credentials following the W3C Verifiable Credentials Data Model v1.1. Issuers create custom JSON-LD schemas with typed attributes, validation rules, batch CSV ingestion, real-time SVG visual certificate rendering, and dark-mode PDF export.

Why It Matters (Business Impact)
  • Zero Credential Forgery: Credentials cannot be altered without invalidating the cryptographic signature and on-chain root.
  • Dynamic Schema Flexibility: Academic degrees, employee IDs, medical certifications, and KYC licenses can be modeled in seconds.
  • High-Throughput Batch Processing: Universities and corporations can mass-issue hundreds of credentials via CSV in a single run.
Technical Deep Dive (Under the Hood)
  • Canonical JSON Normalization: Attributes are normalized via RFC 8785 canonical JSON sorting before SHA-256 computation.
  • EIP-712 Typed Signing: Signatures utilize typed Ethereum domain data (`EcdsaSecp256k1Signature2019`).
  • IPFS Schema Pinning: Schemas are automatically pinned to Pinata IPFS to guarantee permanent public accessibility.

STEP 3

FEATURE 02

EVM On-Chain Anchoring & Instant Revocation Registry

Smart Contracts

Anchored on Ethereum Sepolia (`0x1FE3Dce86E02C28b7B5c1CaCf83127874fb5D778`) and Polygon Amoy, `CredentialRegistry.sol` serves as an immutable cryptographic notary. It supports single and batch anchoring up to 100 credentials per transaction, gas-optimized status lookups, and instantaneous irreversible revocation.

Key Capabilities
  • Batched State Anchoring: `anchorCredentialBatch(bytes32[] hashes)` anchors 100 credentials in one block, cutting gas costs by over 70%.
  • Zero-Latency Status Verification: `isValid(bytes32 hash)` and `getCredentialStatus(bytes32 hash)` return anchored status, timestamp, issuer address, and revocation block in a single RPC query.
  • Issuer Authorization Guards: Only the original issuing wallet address can trigger `revokeCredential(bytes32 hash)`.
Smart Contract Interface (`CredentialRegistry.sol`)
  • `anchorCredential(bytes32 hash)`: Stores `blockAnchored` and `anchoredAt` timestamp; emits `CredentialAnchored`.
  • `revokeCredential(bytes32 hash)`: Sets `revoked = true` and `revokedAt = block.timestamp`; emits `CredentialRevoked`.
  • Gas Efficiency: Compact packing of `uint256` timestamp and `address` saves storage slots on EVM.

FEATURE 03

Zero-Knowledge Privacy Layer (Circom 2.0 & Groth16 zk-SNARKs)

Zero-Knowledge

Holders prove compliance with strict verification policies (such as being over 21, possessing an income within an approved bracket, or holding accreditation from an authorized issuer) without revealing their date of birth, exact salary, or identity. Proving runs entirely in-browser in <250ms via WebAssembly and `snarkjs`.

Circom 2.0 Circuits in Codebase
  • `age-verify.circom` (128 constraints): Proves holder age >= threshold (e.g. 21) using calendar date arithmetic without exposing birthday.
  • `attribute-range.circom` (134 constraints): Asserts numeric value ∈ [`minValue`, `maxValue`] using bitwise comparator components.
  • `issuer-membership.circom` (286 constraints): Proves inclusion of issuer in an authorized Merkle tree root with a private nullifier hash.
Dual Verification Pipeline
  • Client In-Browser: Rapid verification using `snarkjs.groth16.verify()` and `verification_key.json` in <15ms.
  • On-Chain EVM: Verified via `ZKPVerifier.sol` using Ethereum's native BN254 pairing precompile `0x08` (~215,000 gas).
  • Zero Attribute Leakage: Verifier only receives proof points πA, πB, πC and public signals.

FEATURE 04

EIP-5192 Soulbound Credential Tokens (Non-Transferable SBTs)

Smart Contracts

Mint non-transferable Soulbound Tokens (SBTs) directly to holder Web3 addresses via `SoulboundCredential.sol` (`0xC5B743959e651C2cbb60422B3bC44fFD465B46d8`). Implementing the official EIP-5192 standard, tokens are locked to the holder's soul upon minting, preventing secondary sale or credential trading while maintaining real-time revocation sync.

EIP-5192 Standard Compliance
  • `locked(uint256 tokenId)`: Always returns `true` for valid active credentials; emits `Locked(tokenId)`.
  • Transfer Lockout: Overrides `transferFrom`, `safeTransferFrom`, and `approve` to revert immediately with `ErrLockedToken()`.
  • Burn & Revocation Hook: If revoked on `CredentialRegistry.sol`, the badge dynamically reflects revoked state or can be burned by issuer.
Holder Badge Gallery Benefits
  • Public Web3 Portfolio: Holders can showcase verifiable credentials directly on OpenSea, Rarible, or portfolio viewers without risk of transfer.
  • Zero Third-Party Custody: SBT resides in holder's personal wallet address permanently.
  • On-Chain Metadata URI: Resolves to canonical IPFS JSON-LD metadata and SVG badge vector art.

FEATURE 05

ERC-4337 Account Abstraction & Scoped Session Keys

Smart Contracts

Transform ordinary user wallets into programmable Smart Contract Accounts via `SimpleAccount.sol` and `SmartWalletRegistry.sol` (`0xD7a4375C9bA97B6b5E767AfDbCa48c5d99B68196`). Enables gasless transactions sponsored by Paymasters, bundled UserOperations via the canonical ERC-4337 EntryPoint (`0x5FF137D4b0FDCD49DcA30c7CF57E578a026d2789`), and time-limited, scoped session keys.

Account Abstraction Architecture
  • `UserOperation` Struct: Replaces raw transactions with bundled meta-transactions specifying callData, gas limits, and paymaster verification.
  • Paymaster Gas Sponsorship: Verifiers or issuers can sponsor gas fees on behalf of holders, eliminating the requirement for users to hold ETH.
  • Session Key Scoping: Authorize temporary keys with precise allowances (e.g., valid for 2 hours, max 5 credential presentations).
Enterprise Benefits
  • Frictionless Web3 Onboarding: Users interact without managing gas balances or understanding EVM nonces.
  • Granular Operational Security: Even if a session key is compromised, it cannot transfer wallet funds or exceed pre-configured scope.
  • Multi-Sig & Social Recovery Ready: Smart accounts can be upgraded with guardian recovery schemes.

FEATURE 06

Multi-Detector AI Anomaly & 8-Factor Trust Radar

AI & Security

An explainable, deterministic machine learning and behavioral anomaly pipeline (`src/lib/ml/` and `src/services/ai/`) that evaluates every credential verification event in real time. It features 5 statistical anomaly detectors combined with an 8-factor Trust Radar (0–100 score), supplemented by Google Gemini AI fraud analysis.

5 Real-Time Anomaly Detectors
  • Burst / Velocity Detector: Flags automated credential scraping using sliding time-window frequency analysis.
  • Failure Streak Detector: Detects credential enumeration and brute-force attacks from repeated failed signatures.
  • Geographic Velocity Jump: Evaluates physical travel possibility via Haversine distance (>800 km/h triggers supersonic impossible-travel alert).
  • Off-Hours Detector: Identifies presentations occurring outside customary circadian and timezone patterns.
  • Latency Spike Detector: Flags network or proving delays indicating replay attacks or proxy manipulation.
8-Factor Trust Score Radar (0–100)
  • Signature Validity (20 pts) & On-Chain Anchor (20 pts): Cryptographic foundations.
  • Not Revoked (15 pts) & Issuer Reputation (15 pts): Authority status.
  • Not Expired (10 pts) & Historical Verifications (10 pts): Activity consistency.
  • ZK Proof Presented (5 pts) & Credential Maturity (5 pts): Privacy & longevity bonuses.
  • Critical Failure Cap: Any cryptographic or revocation failure hard-caps the total score at 35.

FEATURE 07

Selective Disclosure & Granular Time-Decayed Sharing

Identity & VC

Empowers holders with total sovereignty over personal data through selective attribute disclosure. Holders disclose only essential fields (e.g., revealing graduation status while cryptographically masking GPA and birth date) and issue time-limited sharing links (1 hour, 24 hours, 7 days, 30 days) that expire automatically.

Selective Disclosure Mechanics
  • Attribute Masking: Non-disclosed fields are replaced with cryptographic salted commitments, maintaining proof of whole-document integrity.
  • W3C Verifiable Presentation (VP): Packages disclosed attributes inside a signed VP envelope referencing the original credential ID.
  • Zero Over-Sharing: Verifiers receive strictly what was agreed upon in the verification agreement.
Time-Decay Controls (`credential_shares`)
  • Granular Expiry Windows: Share tokens carry strict `expires_at` timestamps enforced by PostgreSQL RLS and edge functions.
  • Instant Revocation: Holders can kill an active share token with one click from `/holder/present`.
  • Public Verifier Route: Recipient opens `/shared/:token` to inspect the live credential without needing an account.

FEATURE 08

OpenID4VC Protocol Suite (OID4VCI & OID4VP)

Protocols & Storage

Complete implementation of the emerging global standards for decentralized identity interoperability: OpenID for Verifiable Credential Issuance (OID4VCI) and OpenID for Verifiable Presentations (OID4VP). Enables cross-wallet credential issuance via QR codes and verifier-initiated presentation requests.

OID4VCI (Issuance Protocol)
  • Credential Offer URI: Issuers encode pre-authorized codes and endpoint locations into QR codes (`OID4VCIOfferDialog.tsx`).
  • Peer-to-Peer Claim: Holders scan with mobile/web wallet; Deno edge function `oid4vci` authenticates the token and delivers the credential.
  • No Vendor Lock-In: Works seamlessly with any compliant external SSI wallet (e.g. Lissi, Sphereon).
OID4VP (Presentation Exchange)
  • Presentation Definition: Verifiers specify input descriptors (required schema ID, required fields, nonce) in `OID4VPRequestDialog.tsx`.
  • Cryptographic Proof of Nonce: Prevents replay attacks by requiring the presentation to sign the verifier's ephemeral nonce.
  • Automated Edge Validation: `oid4vp` edge function verifies signature, expiry, and on-chain anchor in one round-trip.

Storage Guarantees
  • Zero Cloud Vendor Lock-In: Anyone can mirror or pin the CIDs to their own IPFS node.
  • Auditable Schema Registry: Schemas stored permanently for 100% reliable long-term verification decades later.
  • Idempotent Pinning: Re-pinning identical schemas returns existing CID without redundant bandwidth.
